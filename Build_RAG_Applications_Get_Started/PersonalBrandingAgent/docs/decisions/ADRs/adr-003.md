# ADR-003 — Keep the Existing `data/` Hierarchy as the Semantic Knowledge Base

## Status

Accepted (see `../architecture/rag-architecture.md`).

## Context

The corpus arrived as ten named categories (audit, certificates, projects,
evidence, courses, positioning, stories, vision, writing style, …). A
generic `PersonalProfile` abstraction would flatten distinctions the
downstream layers depend on.

## Decision

`data/` keeps its structure. The context layer maps existing
`category`/`document_type` values into named sections rather than inventing
a new taxonomy, and no generic profile object replaces the corpus unless
evidence shows the structure cannot work.

## Consequences

- Section grouping, coverage reporting, and the evidence/guidance split all
  derive from values that already exist reliably.
- Cost: any genuinely new kind of knowledge needs an explicit category and
  mapping decision instead of landing in a catch-all.
