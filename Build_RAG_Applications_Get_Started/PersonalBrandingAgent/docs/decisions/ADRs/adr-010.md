# ADR-010 — Workflow-Level Evaluation with Fakes Over Real Boundaries

## Status

Accepted (Step 13; see `tests/test_autonomous_evaluation.py`,
`docs/evaluation/autonomous-evaluation.md`).

## Context

Unit tests prove components; only full-workflow scenarios prove the system
behaves correctly when things go wrong — the common case unattended. But
scenarios must not publish, mail, dial out, or touch production state.

## Decision

Eighteen scenarios plus a milestone drive the real boundaries (`run_sync` /
`run_branding`, the real Agent/generator/verifier/publisher/notifier, the
real pipeline and Chroma) with fakes only at the external edges (LLM
client, judge, LinkedIn transport/HTTP, email, credential file, git repos,
isolated state). Every scenario asserts recorded outcomes and persistent
state — never completion, never logs. A socket-blocking fixture fails any
test that reaches the network; the milestone asserts the full outcome
vector twice from clean state, so reproducibility is constructed.

## Consequences

- The suite is the regression gate for every failure contract in the
  system; flakiness is a defect, never retried.
- Cost: fixtures mirror several constructive patterns from earlier suites
  (a deliberate, documented duplication — shared fakes would couple
  evaluation to unit-test internals).
