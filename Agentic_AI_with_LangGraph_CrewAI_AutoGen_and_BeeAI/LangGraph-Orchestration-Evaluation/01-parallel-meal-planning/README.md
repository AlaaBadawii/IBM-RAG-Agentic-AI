# 01 Parallel Meal Planning — Orchestrator-Worker Pattern

Implementation of the *Orchestrator-Worker Pattern* section (cells 17–61) of
`../Agentic Design Patterns in LangGraph-v1.ipynb`: a catering-kitchen workflow in
which a head-chef **orchestrator** splits a meal request into dishes, multiple
**chef workers** write detailed cooking plans in parallel, and a **synthesizer**
merges the plans into one meal guide.

**Status: Implemented guided orchestrator-worker workflow.** [Lab overview](../README.md) · [Course 8](../../README.md) · [Certificate](../../../README.md)

Model provider: **IBM watsonx.ai** (`ChatWatsonx` from the shared root `../llm.py`,
configured via the `WATSONX_*` environment variables). The notebook itself uses
OpenAI; this deviation is intentional and preserved everywhere in this lab.

## How it works

1. **Orchestrator** (`orchestrator.py`) — invokes `planner_pipe`
   (`dish_prompt | llm.with_structured_output(Dishes)`), which asks the LLM to turn the
   user's meal list into a structured list of `Dish` Pydantic objects
   (`name`, `ingredients`, `location`), returned under the state key `sections`.

2. **Fan-out** (`assign_workers.py`) — a conditional-edge routing function that
   returns one `langgraph.types.Send` per dish:
   `Send("chef_worker", {"section": s})`. LangGraph spawns one `chef_worker`
   execution per `Send`, all running in parallel.

3. **Workers** (`chef_worker.py`) — each execution sees only its own slice of state
   (`WorkerState` = one `section` + the aggregated `completed_menu` list). It invokes
   `chef_pipe` (chef persona prompt → LLM) and returns
   `{"completed_menu": [meal_plan.content]}`.

4. **Parallel result collection** — `completed_menu` is annotated with
   `operator.add` in both `OrchestrationState` and `WorkerState`, so LangGraph
   merges every worker's list into one combined list automatically.

5. **Synthesizer** (`synthesizer.py`) — joins the collected worker outputs with
   `\n\n---\n\n` and stores the full text under `final_meal_guide`.

## Graph structure

`graph.py` builds and compiles `orchestrator_worker`:

```
START ──> orchestrator ──(assign_workers / Send)──> chef_worker ──> synthesizer ──> END
                                              (one per dish, in parallel)
```

Nodes: `orchestrator`, `chef_worker`, `synthesizer`.
Edges: `START → orchestrator`; `chef_worker → synthesizer`; `synthesizer → END`;
conditional edges `orchestrator → chef_worker` created by `assign_workers`.

The rendered graph image is `graph.png` in this directory (regenerated by
`python graph.py`).

## Setup and execution

- Configure `.env` next to `../.env.example` (same directory, lab root) with the
  four `WATSONX_*` variables.
- Activate the project-local environment described in the [lab setup](../README.md#python-environment).
- Run from **this lab's root directory** (`LangGraph-Orchestration-Evaluation/`):

```bash
python 01-parallel-meal-planning/agent.py
```

Root-level helpers (`llm`, `print_workflow_info`) are resolved by a small
`sys.path` preamble in `pipe.py` and `graph.py`, matching the convention used in
the sibling [LangGraph Workflow Patterns lab](../../LangGraph-Workflow-Patterns/README.md).
